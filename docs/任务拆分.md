# Tasks: 积分功能开发任务拆分

> 依据：docs/技术Spec.md（design-hdl-points-001）+ docs/产品Spec.md（REQ-001~009）+ docs/需求澄清.md v1.0。
> 目标分支：`feat/points-feature-nzt7`（仓库 `zou646/deliveryai-demo-t3xgji`）。
> 任务按依赖排序：先状态与计算层，再 UI 与装配，后端无变更，随后自动化用例，最后验证与交付。每项任务交付一个可观察结果并可勾选验证。

## 1. 前端 - 状态与计算层

- [ ] 1.1 扩展 `src/types.ts`：新增 `PointEntryType`、`PointEntry`（含 `refId?`）、`PointsCoupon`、`PointsState`、`PointsTier`；`AppState` 增加 `points: PointsState`；`AppAction` 增加 `REDEEM_POINTS`、`GRANT_POINTS`、`APPROVE_CANCEL`、`EXPIRE_POINTS`，并将 `PAY` 扩展为 `{ type: 'PAY'; couponIds: string[] }`（契约见技术Spec §4.1）。
- [ ] 1.2 新增 `src/data/points.ts`：导出 `POINTS_TIERS`（500=¥5 / 1000=¥10 / 2000=¥20）、`POINTS_VALID_MONTHS=12`、`POINTS_PER_YUAN=100`（技术Spec §9 常量表）。
- [ ] 1.3 新增 `src/lib/checkout.ts`：实现纯函数 `calcCheckout(items, coupons, selectedCouponIds)`，返回 `{ subtotal, discount, basePayable, couponValue, couponCap, effectiveCoupon, payable, earned }`；subtotal 排除 `cancelState==='approved'` 项；金额以分舍入；`earned = Math.ceil(basePayable)`（技术Spec §3.2）。
- [ ] 1.4 新增 `src/lib/points.ts`：实现 `pointsBalance(entries)`（= Σearn − Σredeem − Σrefund − Σexpire，earn 仅未过期）、`pointsForAmount(amount)`（向上取整）、`expiresAtFor(createdAt)`（+12 个月 ISO）、过期处理辅助（技术Spec §3.2/§4.1）。
- [ ] 1.5 扩展 `src/state/orderReducer.ts`：`initialState.points`（balance 0 / entries [] / coupons []）；实现 `PAY`（幂等：已 paid 原样返回；计算入账、核销勾选券 used、追加 earn 明细、更新余额）、`REDEEM_POINTS`（余额与档位校验、扣减、redeem 明细、发券）、`GRANT_POINTS`（演示发放，note=演示发放）、`APPROVE_CANCEL`（approved；paid 时按 `ceil(金额)` 回退并以 0 截断、追加 refund 明细）、`EXPIRE_POINTS`（未过期 earn 全部过期、expire 明细 refId 防重、余额剔除）；`RESET` 自动清空（复用 initialState）。

## 2. 前端 - UI 与装配

- [ ] 2.1 新增 `src/components/PointsSection.tsx`：会员弹窗积分区（余额卡片 + 「积分明细」面板 + 「积分兑换」面板三面板切换）；明细倒序渲染（类型徽标 / ±变动值 / 时间 / 说明 / earn 显示到期时间）；兑换面板按 `POINTS_TIERS` 渲染、余额不足禁用并提示「积分不足」、空余额显示空态「暂无可用积分」；明细空态「暂无积分记录」（REQ-002/003/008）。
- [ ] 2.2 修改 `src/components/TopBar.tsx`：接收 `points` / `onRedeem`，在会员弹窗挂载 `PointsSection`；「可用权益」计数 = 4 + 未使用兑换券数（REQ-003.4）。
- [ ] 2.3 修改 `src/components/CheckoutView.tsx`：新增「可用兑换券」勾选区（未使用券，无券时隐藏/置灰并说明）；勾选后经 `calcCheckout` 实时重算应付并展示「使用兑换券 −¥X」明细行；触发 50% 上限时截断并提示「超出部分不可用」；支付按钮提交 `onPay(selectedCouponIds)`；paid 分支展示「获得 N 积分」与「当前积分 M」（REQ-001/004/008）。
- [ ] 2.4 修改 `src/components/DemoConsole.tsx`：新增「退菜确认」区（`cancelState==='requested'` 的项 + 「确认退菜」按钮 → `onApproveCancel(uid)`，无待确认项时空态）；新增「积分演示」区（当前余额展示 + 发放数量输入（默认 500）+「模拟发放积分」→ `onGrantPoints(n)` +「模拟过期」→ `onExpirePoints()`）（REQ-005/006）。
- [ ] 2.5 修改 `src/components/OrderView.tsx`：`cancelState==='approved'` 展示「已确认退菜」态（区别于 requested 的「等待确认」）（REQ-005）。
- [ ] 2.6 修改 `src/App.tsx`：向 TopBar / CheckoutView / DemoConsole 下传 points 与新回调；`onPay={(ids) => dispatch({ type:'PAY', couponIds: ids })}`、`onRedeem`、`onApproveCancel`、`onGrantPoints`、`onExpirePoints`（技术Spec §4.2）。
- [ ] 2.7 修改 `src/i18n.ts`：按技术Spec §4.3 新增 `points.*` 组与 `checkout.*` / `console.*` / `message.*` 扩展，zh / en 同步（REQ-009）。

## 4. 自动化用例（E2E）

> 用例规范见 docs/agent-testing.md：`REQ-xxx` 命名、describe 按功能域、单用例单验收点、正反路径、可乱序独立执行；数据准备优先使用 DemoConsole「模拟发放积分」做确定性种子。

- [ ] 4.1 新增 `e2e/points.spec.ts` 导航与种子辅助函数：进入 menu/order/checkout、打开会员弹窗、打开 DemoConsole 并「模拟发放 N 积分」。
- [ ] 4.2 REQ-001 获取：支付后按 `basePayable` 正确入账（如 p1+p3+p4=¥158 → base 128 → 128 积分）；支付成功页展示「获得 128 积分」与余额；已 paid 重复结账不重复入账（明细条数 / 余额不变）。
- [ ] 4.3 REQ-002 查看：会员弹窗展示余额；明细倒序且字段齐全（类型 / ±变动值 / 时间 / 说明 / 到期时间）；新会话明细空态「暂无积分记录」。
- [ ] 4.4 REQ-003 兑换：种子 600 → 兑换 500 → 余额 100、券 +1、明细「使用 −500」；余额不足（如 100 < 500）兑换禁用并提示「积分不足」；空余额兑换区空态「暂无可用积分」。
- [ ] 4.5 REQ-004 叠加：base 128 + ¥10 券 → 应付 118，且支付后入账仍为 128（基数不变）；base 80 + 券 ¥20/¥30 合计 50 > 上限 40 → 实际抵扣 40、应付 40、提示超出部分不可用、不找零不为负。
- [ ] 4.6 REQ-005 回退：支付后（如余额 128）退菜确认 ¥42 项 → 余额 86、明细「回退 −42」；未支付退菜确认 → 不回退积分仅 approved；多笔回退超过余额 → 余额 0 不为负。
- [ ] 4.7 REQ-006 过期：earn 明细展示到期时间（+12 个月）；DemoConsole「模拟过期」→ 余额剔除、明细「过期」、兑换不可用。
- [ ] 4.8 REQ-007 一致性：混合操作（earn + redeem + refund + expire）后，展示余额 = 明细 ± 变动值合计。
- [ ] 4.9 REQ-008 空态与提示：明细空态、无可用券（结账区隐藏/置灰并说明）、积分不足、抵扣超上限提示逐一断言。
- [ ] 4.10 REQ-009 多语言：切换 EN 后会员弹窗 / 结账券区 / 支付成功页积分文案英文且无缺失 key。
- [ ] 4.11 回归：`e2e/view-routing.spec.ts`、`e2e/super-spicy.spec.ts` 保持全绿。
